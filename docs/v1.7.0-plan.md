# v1.7.0 实施计划 — HTTPS 与 HTTP 完整化

> 关联文档：[版本路线图](roadmap.md)、[v1.6.0 实施计划](v1.6.0-plan.md)

本文档是 v1.7.0 的实施计划。v1.7.0 的主题是 **把 TLS 做成可生产使用的传输层，并补齐 HTTP 服务端能力**：
TLS 校验/SNI/ALPN/mTLS/证书热加载、H2 over TLS、静态文件、中间件管线、响应压缩、H2 流式响应。

本机当前没有可用的 Linux 构建环境，本文只做规划与代码走查；所有编译、单测、压测统一在 CI / Linux 开发机执行。

---

## 一、已确认决策

| 决策项         | 结论                                                                                              |
|----------------|---------------------------------------------------------------------------------------------------|
| 版本范围       | 按 roadmap 全量交付：TLS/HTTPS + 静态文件 + 中间件 + 压缩 + H2 streaming，不拆版本                |
| 客户端证书校验 | **默认开启**：校验链 + 主机名 + SNI，使用系统 CA 或配置 `ca_file`；可用 `verify_peer: 0` 显式关闭 |
| 中间件形态     | `ServletDispatch` 前置 Filter 链，H1 / H2 / SSE 统一生效，可短路、可后置处理                      |
| TLS 握手位置   | 从 accept worker 移到 io worker：accept 只建 TCP 连接，握手在 `handleClient` 前完成               |
| 证书热加载     | inotify 监听证书/私钥文件，原子替换 `SSL_CTX`；新连接立即生效，存量连接保持旧 ctx                 |
| 协议选择       | TLS 用 ALPN 决定 `h2` / `http/1.1`；明文保留 h2c preface 探测，`negotiateH2` 仅对明文生效         |
| H2 流式        | 重构 `h2_session` 写路径，`DATA` 走 nghttp2 data provider + 每流有界队列，SSE 不再直接写 socket   |
| 压缩范围       | 仅对非流式、可压缩类型、超过阈值的响应做 gzip/deflate；不压缩 206/304/SSE/已编码响应              |
| 新增三方依赖   | 无。OpenSSL / nghttp2 / zlib / inotify 均已在用                                                   |

| 能力               | 现状                                                                               | v1.7.0 差距                                         |
|--------------------|------------------------------------------------------------------------------------|-----------------------------------------------------|
| 客户端 TLS 校验    | `SSLSocket::connect()` 只 `SSL_new` + 一次 `SSL_connect`，未设置 verify、SNI、ALPN | 校验链、主机名、SNI、ALPN、非阻塞握手、错误映射     |

## 五、关键设计

### 5.1 TLS 上下文与配置

新增 `chen::tls::TlsConfig`，`TcpServerConf` 只做 YAML 映射，具体 SSL 逻辑收敛到 `TlsContext`：

```cpp
namespace chen::tls {

struct SniCert {
    std::string host;        // 精确域名或 *.example.com
    std::string cert_file;
    std::string key_file;
};

struct TlsConfig {
    bool enabled = false;
    bool server = true;

    std::string cert_file;
    std::string key_file;
    std::string ca_file;
    std::string ca_path;
    std::string ciphers;
    std::string ciphersuites;

    std::string min_version = "TLS1.2";
    std::string max_version;              // 空 = 不限制

    bool verify_peer = true;              // 客户端：校验服务端
    bool verify_client = false;           // 服务端：mTLS
    int verify_depth = 4;

    std::vector<std::string> alpn = {"h2", "http/1.1"};
    std::vector<SniCert> sni;

    bool prefer_server_ciphers = true;
    bool session_tickets = true;
    bool hot_reload = true;
    uint64_t handshake_timeout_ms = 10000;
};

class TlsContext {
public:
    typedef std::shared_ptr<TlsContext> ptr;

    static ptr CreateServer(const TlsConfig& conf);
    static ptr CreateClient(const TlsConfig& conf);

    SSL_CTX* get() const;
    const TlsConfig& getConfig() const;

    // 重新读取 cert/key/ca，成功后一次性替换内部 SSL_CTX
    bool reload(std::string* err = nullptr);

    // 握手完成后读取协商结果
    static std::string GetAlpn(SSL* ssl);
    static bool IsAlpnH2(SSL* ssl);
};

} // namespace chen::tls
```

实现要点：

- 服务端：`TLS_server_method()`，禁用 SSLv2/v3、压缩、重协商；`SSL_CTX_set_min_proto_version`。
- 客户端：`TLS_client_method()`，`SSL_CTX_set_default_verify_paths()` 或配置 CA；`SSL_CTX_set_verify(SSL_VERIFY_PEER)`。
- **主机名校验不能只靠 `SSL_get_verify_result`**：连接前用 `SSL_set_tlsext_host_name()` 设置 SNI，并用
  `X509_VERIFY_PARAM_set1_host()` 绑定目标主机名；否则任意受信 CA 签发的其他域名证书都会通过。
- SNI 多证书：`SSL_CTX_set_tlsext_servername_callback()` 中按 host 选择备用 `TlsContext`，然后
  `SSL_set_SSL_CTX(ssl, alt->get())`；备用 ctx 与主 ctx 一起持有、一起 reload。
- ALPN：服务端 `SSL_CTX_set_alpn_select_cb()` 按配置优先级选择；客户端
  `SSL_CTX_set_alpn_protos()`。协商结果由 `SSL_get0_alpn_selected()` 读取。
- mTLS：`SSL_VERIFY_PEER | SSL_VERIFY_FAIL_IF_NO_CLIENT_CERT`，加载 `ca_file`，设置
  `SSL_CTX_set_verify_depth()`；可选 `SSL_CTX_set_client_CA_list()` 下发 CA 列表。
- TLS 1.3 下 `SSL_read` 可能因 post-handshake 消息返回 `WANT_WRITE`，任何读写循环都必须同时处理
  `WANT_READ` 和 `WANT_WRITE`，不能假设方向固定。

### 5.2 SSLSocket 重构与非阻塞握手

保留 `SSLSocket` 作为传输层，但把“握手”从 `init()` 中拆出来：

```cpp
class SSLSocket : public Socket {
public:
    static SSLSocket::ptr CreateTCP(Address::ptr address, const tls::TlsConfig& conf = {});

    // accept 时默认不握手；TcpServer 在 io worker 中显式调用
    bool handshake(uint64_t timeout_ms = 0);

    bool setTlsContext(tls::TlsContext::ptr ctx);
    tls::TlsContext::ptr getTlsContext() const;
    std::string getAlpnProtocol() const;
    bool isAlpnH2() const;

    // 兼容旧接口，内部转成 TlsConfig + reload
    bool loadCertificates(const std::string& cert_file, const std::string& key_file);
};
```

- `SSLSocket::connect()`：TCP 连接成功后创建客户端 `TlsContext`，设置 SNI/hostname/ALPN，再走统一的
  `handshake()` 循环；握手失败返回明确错误（证书过期、主机名不匹配、协议版本过低等），日志包含
  `X509_verify_cert_error_string` / `ERR_error_string`。
- `SSLSocket::accept()`：只 `accept(2)` + `SSL_new`， **不再 `SSL_accept`**。避免慢握手占住 accept worker。
- `TcpServer::startAccept()`：accept 成功后仍投递到 `m_ioWorker`，在 `handleClient` 前执行握手：

```cpp
m_ioWorker->schedule([this, self = shared_from_this(), client]() {
    if (m_ssl) {
        auto ssl = std::dynamic_pointer_cast<SSLSocket>(client);
        if (!ssl || !ssl->handshake(m_handshakeTimeoutMs)) {
            client->close();
            // 计数 + 释放限流
            return;
        }
    }
    handleClient(client);
    // 清理
});
```

- 读写：`SSL_write_ex` / `SSL_read_ex` 统一封装，遇到 `WANT_READ/WANT_WRITE` 时复用现有 hook 思路：
  `IOManager::addEvent(fd, event)` + `Fiber::YieldToHold()`，带超时定时器；`SSL_ERROR_SYSCALL` 且有
  `errno == EAGAIN/EWOULDBLOCK` 时按可重试处理。
- 退出/关闭：`SSL_shutdown` 最多尝试一次，失败直接 close，避免半关闭连接拖住 drain。
- 指标：

| 指标                                  | 类型      | 标签                                             |
|---------------------------------------|-----------|--------------------------------------------------|
| `chen_tls_handshakes_total`           | Counter   | server, result（ok/verify_failed/timeout/error） |
| `chen_tls_handshake_duration_seconds` | Histogram | server                                           |
| `chen_tls_cert_reload_total`          | Counter   | server, result                                   |
| `chen_tls_alpn_total`                 | Counter   | server, protocol                                 |

### 5.3 配置扩展

```yaml
servers:
  - address: ["0.0.0.0:8443"]
    type: http
    name: game_https
    ssl: 1
    cert_file: /etc/chen/certs/server.crt
    key_file: /etc/chen/certs/server.key
    ca_file: /etc/chen/certs/ca.crt      # 可选；mTLS 或私有 CA 时使用
    verify_client: 0                     # 1 = 要求客户端证书（mTLS）
    verify_depth: 4
    min_tls_version: TLS1.2
    alpn: ["h2", "http/1.1"]
    handshake_timeout_ms: 10000
    cert_reload: 1
    sni:
      - host: api.example.com
        cert_file: /etc/chen/certs/api.crt
        key_file: /etc/chen/certs/api.key
```

- 保留旧配置：只写 `ssl: 1` + `cert_file` + `key_file` 仍然可用，其余走默认值。
- `TcpServerConf` 新增字段，并同步 `operator==`、`LexicalCast` 双向序列化与 `toString()`。
- `HttpConnection` / `WSConnection` 的 https/wss 客户端默认使用系统 CA 校验；新增
  `HttpConnection::Create(url, timeout, const tls::TlsConfig&)` 重载用于私有 CA / 自签名场景。
- 全局客户端默认值放在 `http_client` 配置节（`verify_peer` / `ca_file` / `alpn`），由
  `TlsContextMgr::clientDefault()` 读取；未配置时 `verify_peer = true`。

### 5.4 ALPN 与 H2 over TLS

`HttpServer::handleClient` 改为：

1. 若 `client` 是 `SSLSocket`：
    - ALPN 为 `h2` → `H2Session`
    - ALPN 为 `http/1.1` 或为空 → `HttpSession`
2. 明文连接：
    - `type == "http2"` → `H2Session`
    - `negotiateH2 == 1` 且 preface 匹配 → `H2Session`
    - 否则 `HttpSession`

约束：

- `type: http2` + `ssl: 1` 时，若客户端未协商到 `h2`，直接以 `no_application_protocol` 告警关闭，避免
  半懂不懂的客户端把 HTTP/1.1 流量送进 H2 解析器。
- H2 over TLS 使用 `:scheme = https`；H2C 保持 `http`。
- TLS 1.2 下按 RFC 7540 禁用黑名单套件；TLS 1.3 不受影响。
- `negotiateH2` 只对明文生效，文档与配置注释同步更新。

### 5.5 证书热加载

- 扩展 `FileWatcher`：
    - `watchDir(dir, cb, extensions)`：`extensions` 为空表示全部文件；默认仍为 `.yml/.xml`，保持配置热加载行为不变。
    - `watchFiles(files, cb)`：按父目录 + basename 过滤，避免证书目录里其他文件触发重载。
- 每个 TLS server 持有 `TlsContextMgr`：
    - 主证书 + SNI 证书全部注册监听；
    - 收到事件后 **debounce 200ms**（certbot/脚本通常连续写多个文件）；
    - 全部文件可读、证书与私钥匹配后才原子替换；失败保留旧 ctx 并打 `ERROR`，指标记 `result=error`；
    - 替换只更新“监听 socket 当前使用的 ctx”，已 accept 的连接继续持有旧 `TlsContext::ptr`，直到连接关闭。
- **master/worker 关键约束**：监听 fd 与 TLS ctx 由 master 创建，worker fork 后继承的是 fork 时刻的 ctx。
  若证书在 master 内存中已经过期，SIGHUP 拉起的新 worker 仍会带旧证书。因此：
    - worker 在 fork 后、开始 accept 前，必须调用 `server->reloadCertificatesFromConf()` 从磁盘重新加载；
    - 运行期轮换由各 worker 的 `FileWatcher` 处理；
    - master 不参与证书 reload，避免多进程同时写状态。
- 兼容：`TcpServer::loadCertificates(cert, key)` 保留，内部构造 `TlsConfig` 后走 `TlsContext`。

### 5.6 HTTP Filter 链

```cpp
class FilterChain;

class HttpFilter {
public:
    typedef std::shared_ptr<HttpFilter> ptr;
    virtual ~HttpFilter() = default;

    // 调用 next->doFilter() 继续；不调用即短路；可在 next 返回后做后置处理
    virtual void doFilter(HttpRequest::ptr req,
                          HttpResponse::ptr rsp,
                          HttpSession::ptr session,
                          FilterChain::ptr next) = 0;

    // 数值小的先执行（外层）
    virtual int order() const { return 0; }
};

class FilterChain {
public:
    typedef std::shared_ptr<FilterChain> ptr;

    void addFilter(HttpFilter::ptr filter);
    void doFilter(HttpRequest::ptr req, HttpResponse::ptr rsp, HttpSession::ptr session);
    bool empty() const;
};
```

`ServletDispatch` 新增：

```cpp
void addFilter(HttpFilter::ptr filter);                          // 全局
void addFilter(const std::string& prefix, HttpFilter::ptr f);     // 路径前缀
void clearFilters();
```

执行顺序：

```
matchForRequest → 全局 filter → 前缀 filter → servlet
```

- 过滤器按 `order()` 稳定排序，同 order 保持注册顺序；启动/`onServerReady` 后不再修改，避免请求路径加锁。
- 短路约定：filter 不调用 `next->doFilter()` 即结束；若响应未设置，dispatch 补 500。
- H1 流式 body：`HttpServer` 先判断 `slt->isStreamingBody()` 决定是否读 body，再调用 `dispatch->handle()`；
  filter 短路且未消费 body 时，沿用现有 `session->drainBody()` 的约定。
- H2 的 `processStream()` 也走 `dispatch->handle()`，因此 filter 天然覆盖 H2；SSE 重构后同样覆盖。
- 内置 filter：

| Filter            | order | 行为                                                                                                             |
|-------------------|-------|------------------------------------------------------------------------------------------------------------------|
| `RequestIdFilter` | 100   | 复用请求 `X-Request-Id`，否则 `RandomUtil` 生成；回写响应头，挂到请求属性                                        |
| `CorsFilter`      | 200   | 允许源/方法/头/凭证/预检缓存；`OPTIONS` 预检短路 204；`Vary: Origin`                                             |
| `AccessLogFilter` | 300   | 调用 next 后记录单行 JSON：ts、request_id、method、path、status、bytes、duration_ms、remote、proto、ua；支持采样 |

> 鉴权、限流仍按 roadmap 放在 v1.9.0；本版本只提供可挂载的管线与示例 filter。

### 5.7 静态文件 Servlet

```cpp
struct StaticFileOptions {
    std::vector<std::string> index_files = {"index.html", "index.htm"};
    bool allow_dotfiles = false;
    bool follow_symlinks = false;
    bool enable_range = true;
    bool enable_etag = true;
    uint64_t max_age = 3600;
    std::string cache_control = "public, max-age=3600";
    size_t io_chunk = 64 * 1024;
};

class StaticFileServlet : public Servlet {
public:
    typedef std::shared_ptr<StaticFileServlet> ptr;
    StaticFileServlet(const std::string& root, StaticFileOptions opts = {});
    int32_t handle(HttpRequest::ptr req, HttpResponse::ptr rsp, HttpSession::ptr session) override;
};
```

处理流程：

1. 仅允许 `GET` / `HEAD`，其余返回 405 + `Allow`。
2. URL path 解码后拼接 root；拒绝 `..`、空字节、反斜杠；`realpath` 后必须仍在 root 内；默认不跟随符号链接；
   点文件默认 404。
3. 目录：尝试 `index_files`；不存在则 404（本版本不做 autoindex）。
4. `stat` 后设置：
    - `Content-Type`：内置 MIME 表，未知为 `application/octet-stream`；
    - `Content-Length`、`Last-Modified`（RFC 7231 日期）、`ETag`（`W/"size-mtime_ns-inode"`）；
    - `Cache-Control`、`Accept-Ranges: bytes`。
5. 条件请求优先级：`If-None-Match` > `If-Modified-Since`；命中返回 304，无 body。
6. Range：
    - 单区间 `bytes=start-end`、`bytes=start-`、`bytes=-suffix`；
    - 返回 206 + `Content-Range`；
    - 非法/越界返回 416 + `Content-Range: bytes */size`；
    - 多区间本版本降级为 200 全量（文档注明），避免 multipart/byteranges 复杂度；
    - `If-Range` 不匹配时忽略 Range 返回 200。
7. 发送：
    - H1 非 TLS：新增 `Socket::sendfile()`（底层 `sendfile(2)`，非阻塞 `EAGAIN` 走 `IOManager` 等待）；
    - H1 + TLS：不能 sendfile，按 `io_chunk` 读文件 + `SSL_write`；
    - H2：按 `io_chunk` 调用 `H2Stream::sendData()`，遵守流控与背压；
    - `HEAD` 只发头。
8. 打开文件失败：404（`ENOENT`）或 403（`EACCES`），不泄漏绝对路径。

安全注意：

- 必须用 `O_RDONLY | O_CLOEXEC` 打开后再 `fstat`，避免 `realpath` 与 open 之间的 TOCTOU；以打开的 fd 为准。
- 不允许通过静态文件 servlet 暴露 `.git`、`.env`、证书私钥；点文件默认拒绝，root 建议单独目录。
- 压缩与 Range 不叠加：`206` 不压缩；`ETag` 在压缩时保持并追加 `Vary: Accept-Encoding`（或改为弱 ETag）。

### 5.8 响应压缩

```cpp
struct CompressionOptions {
    bool enabled = true;
    size_t min_length = 1024;
    int level = 6;
    std::vector<std::string> types = {
        "text/*", "application/json", "application/javascript",
        "application/xml", "image/svg+xml"
    };
};

bool ApplyCompression(HttpRequest::ptr req,
                      HttpResponse::ptr rsp,
                      const CompressionOptions& opts);
```

- 解析 `Accept-Encoding` 的 q 值；优先 gzip，其次 deflate；`identity;q=0` 且无可接受编码时返回 406。
- 仅在以下条件全部满足时压缩：
    - 非流式（`rsp->isStreaming() == false`）、非 `HEAD`；
    - 状态码允许 body（非 204/304，非 1xx）；
    - 未设置 `Content-Encoding`；
    - `Content-Type` 命中白名单；
    - body 长度 >= `min_length`。
- 压缩后：设置 `Content-Encoding: gzip|deflate`、`Vary: Accept-Encoding`、新的 `Content-Length`；
  `ETag` 仍是同一资源标识（语义上应随表示变化，建议同时改为弱 ETag，文档注明）。
- 接入点：
    - H1：`HttpServer` 在 `session->sendResponse(rsp)` 前调用；
    - H2：`H2Session::processStream()` 在 `postCommand(RESPONSE)` 前调用；
    - 静态文件：不单独压缩，统一走上述入口；大文件动态压缩成本高，建议业务侧预生成 `.gz` 或 CDN。
- 配置：`TcpServerConf` 新增 `compression`、`compression_min_length`、`compression_types`；默认开启，
  阈值 1024，类型白名单如上。可通过 `args` 覆盖，便于灰度。

### 5.9 H2 流式响应

现状问题：

- `Command::DATA` 是 TODO，`H2Stream::sendData()` 投递后无人消费；
- `H2Session::run()` 用 250ms `recv` 超时轮询命令队列，SSE 延迟不可接受；
- `SSESession` 直接向 socket 写 HTTP/1.1 响应头，H2 下会产生非法字节流。

重构方案：

1. **写路径去轮询**：`H2Session` 增加 `std::mutex m_sessionMutex`，所有 nghttp2 调用串行化。
    - 流 fiber 调 `sendResponse` / `sendData` 时，在锁内 `nghttp2_submit_*` 后立即
      `nghttp2_session_mem_send()` + 写 socket；
    - 读 fiber 在锁内 `nghttp2_session_mem_recv()`，随后同样 flush 控制帧；
    - 不再依赖 250ms 轮询，SSE/流式数据到达即发送。
2. **每流队列**：`H2Session` 维护 `unordered_map<int32_t, shared_ptr<StreamState>>`，`StreamState` 包含：
    - 有界 `std::deque<std::string>`（默认 1MB/流）；
    - `bool end_stream`、`bool closed`、`size_t queued_bytes`；
    - 读回调从队列取数据，空则返回 `NGHTTP2_ERR_DEFERRED`；
    - 生产者 `sendData()` 入队后调用 `nghttp2_session_resume_data()` 并 flush。
3. **背压**：队列满时 `sendData()` 通过 `addConditionTimer(1ms)` 让出 fiber 并重试，直到低于水位或流关闭；
   超过 `send_timeout_ms` 返回错误。避免无界内存增长。
4. **生命周期**：`m_streams` 改存 `shared_ptr<StreamState>`；`on_stream_close()` 标记 closed 并从 map 移除，
   正在写的 fiber 通过 shared_ptr 感知关闭，向已关闭流写返回错误而不是崩溃。
5. **静态文件 / SSE 统一**：`H2Stream` 继承 `HttpSession`，新增虚接口：

```cpp
// HttpSession
virtual int sendData(const void* buffer, size_t length, bool end_stream = false);
virtual int sendResponseHeader(HttpResponse::ptr rsp);
```

- H1 实现：`sendResponseHeader` 写状态行+头；`sendData` 写 body。
- H2 实现：`sendResponseHeader` 提交 HEADERS（不带 END_STREAM）；`sendData` 提交 DATA。

6. **SSE 重构**：
    - `SSESession` 不再持有裸 `Socket`，改为包装 `HttpSession::ptr`；
    - `sendSSEHeaders()` 构造 `HttpResponse`（`Content-Type: text/event-stream`、`Cache-Control: no-cache`、
      `X-Accel-Buffering: no`），调用 `session->sendResponseHeader()`；
    - `sendEvent` / `sendComment` / `sendRetry` 走 `session->sendData()`，H1/H2 共用；
    - 保留 `SSEServlet` 的 `onConnect/onClose` 语义，业务代码无需感知传输。
7. **流控**：`sendData` 返回实际入队字节数；连接级/流级窗口由 nghttp2 管理，data provider 每次只取
   `min(length, queued)`；不手动改窗口，除非后续压测证明需要。

## 七、验收标准

### TLS / HTTPS

- `openssl s_client -connect 127.0.0.1:8443 -alpn h2` 协商出 `h2`，`-alpn http/1.1` 协商出 HTTP/1.1。
- 客户端默认拒绝：未知 CA、过期证书、主机名不匹配、协议版本低于 1.2。
- mTLS：未提供客户端证书时握手失败；正确证书通过；错误 CA 拒绝。
- SNI：不同域名返回对应证书，默认证书兜底。
- 证书轮换：替换文件后 1s 内新连接使用新证书，存量连接不中断；坏文件不生效且保留旧证书。
- 慢握手不阻塞 accept：并发 100 个只建 TCP 不握手的连接，正常 HTTPS 请求仍能在 1s 内完成。

### HTTP

- 静态文件：`curl -I`、`Range`、`If-None-Match`、`If-Modified-Since`、`HEAD`、404/405/416 全部符合预期；
  路径穿越与点文件返回 404/403。
- 压缩：`curl --compressed` 正确解压；`Vary: Accept-Encoding` 存在；206/304/SSE 不压缩。
- 中间件：CORS 预检 204；`X-Request-Id` 透传/生成；访问日志为合法单行 JSON。
- SSE over H2：事件端到端延迟 < 100ms（本机回环），无 HTTP/1.1 字节混入；H1 SSE 无回归。
- H2 大响应：100MB 文件分块传输，进程 RSS 不随文件大小线性增长。

### 回归

- 现有 `test_http_server`、`test_h2_server`、`test_ws_server`、`test_sse_server`、`test_rpc_*` 全部通过。
- 明文 HTTP、h2c、WebSocket、RPC、Game 协议不受 TLS 改动影响。
- 热重载（SIGHUP）后新 worker 使用磁盘上的最新证书。

> 本机无 Linux 构建环境，以上验收在 CI / Linux 开发机执行；规划阶段不运行编译。

|----------------------------|--------------------------------|-------------------------------------------------------------------------------|

| Filter 短路与流式 body     | keep-alive 连接残留 body       | 沿用 `drainBody()`；测试覆盖                                                  |
| 文档超前                   | 使用者误以为已有静态文件       | PR5 修正 README；发布前全量校对                                               |

## 十、待确认事项

以下为本文档的建议默认值，实施前可调整：

1. **压缩默认开启**：是否担心 CPU 成本？可改为默认关闭、按 server 开启。
2. **静态文件多区间 Range**：本版本降级为 200 全量，是否可接受？
3. **`AccessLogFilter` 是否纳入内置**：v1.6.0 曾规划但未交付；若担心日志量，可只保留接口与示例。
4. **H2 背压等待策略**：1ms 定时重试 vs 引入 wake fd；前者实现简单，后者延迟更低。
5. **worker 握手线程**：先复用 `io_worker`，还是为 TLS 握手单独建 worker 池（影响配置与容量模型）。
