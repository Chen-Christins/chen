# v1.6.0 实施计划 — 可观测性与稳定性

> 关联文档：[版本路线图](roadmap.md)

本文档是 v1.6.0 的最终实施计划，已确认以下设计决策：

| 决策项 | 结论 |
|--------|------|
| Admin 服务形态 | 独立 `type: admin` server，独立端口 |
| 长连接 draining | HTTP/2 发 GOAWAY、WS 发 CLOSE 1001、SSE/流式直接关闭，deadline 后强断 |
| 访问日志格式 | 单行 JSON |
| Readiness 范围 | 仅全局 `ServiceState`，v1.6.0 不做业务探针 |

---

## 一、范围

| 主题 | 交付物 |
|------|--------|
| 异步日志 | 有界队列 + 独立日志线程、溢出策略、fork/reload 安全、日志指标 |
| Metrics | 指标注册表、Prometheus `/metrics`、内置运行时/网络/RPC 指标 |
| Admin/Health | `admin` server、`/healthz`、`/readyz`、`/debug/*` |
| 访问日志 | HTTP/1.1 + HTTP/2 单行 JSON、采样、请求 ID |
| 优雅 draining | 停止 accept → 等在途完成后关闭，覆盖 HTTP/WS/RPC/Game/H2 |
| 测试/CI | ctest 接入、新功能测试、GitHub Actions 构建 + 测试 + ASAN |

**明确不做**：TLS/HTTPS、H2 over TLS、静态文件、动态 `servers`、UDP 接入、异步 DNS、RPC 重试/熔断、业务 readiness 探针。

### 复用现有框架能力

新增代码优先复用已有封装，不重复造轮子：

| 能力 | 框架组件 |
|------|----------|
| 单例 | `Singleton` / `LeakySingleton`（`util/singleton.h`） |
| 锁 / RAII | 短临界区用 `SpinLock`；含分配/容器操作或可能争用时用 `std::mutex` |
| 原子操作 | 指标热路径用 `std::atomic` + `memory_order_relaxed`（跨架构避免全屏障）；通用原子操作可用 `Atomic` |
| 不可拷贝 | `Noncopyable`（`util/noncopyable.h`） |
| 类型转字符串 | `TypeUtil::ToString`（`util/type_util.h`） |
| 字符串处理 | `StringUtil`（`util/string_util.h`） |
| 时间 | `TimeUtil` / `GetCurrentMs` / `GetCurrentUs`（`util/time_util.h`） |
| 随机数 / 请求 ID | `RandomUtil`（`util/random_util.h`） |
| JSON | `JsonUtil` + jsoncpp（`util/json_util.h`） |
| 断言 / 分支预测 | `ASSERT` / `ASSERT_MSG` / `LIKELY` / `UNLIKELY`（`util/macro.h`） |

### 关键约束

- **fork 安全**：`Application::spawnWorker()` 在 fork 前必须停止异步日志线程并 flush，子进程启动后重新拉起；否则子进程会继承处于加锁状态的 mutex。
- **日志生命周期**：`LogEvent` 当前强持有 `Logger::ptr`，异步队列会形成 `logger → appender → queue → event → logger` 循环引用。改为 `weak_ptr<Logger>` + 保存 `logger_name`。
- **Admin 端口**：由 master 统一 bind、worker 继承，与现有 `TcpServer` 模型一致；reload 期间新旧 worker 可能都持有监听 fd，短暂出现 readiness 503 属预期。
- **单 active worker 假设**：当前 master 同时只有一个 active worker，Metrics 无需跨进程聚合；reload 重叠窗口内 scrape 可能落到旧 worker。

## 三、PR 拆分与具体任务

### PR1 — Metrics 核心

**新增**

- `chen/metrics/metrics.h/.cc`
- `chen/metrics/README.md`
- `tests/test_metrics.cc`
- `tests/test_metrics_bench.cc`（Release 下的多线程微基准）

**API**

```cpp
namespace chen::metrics {

using Labels = std::vector<std::pair<std::string, std::string>>;

class Counter   { void inc(uint64_t v = 1); uint64_t value() const; };
class Gauge     { void set(int64_t v); void add(int64_t v); int64_t value() const; };
class Histogram { void observe(double v); };

class Registry {
public:
    Registry() = default;

    Counter*   getCounter(const std::string& name, const std::string& help,
                          const Labels& labels = {});
    Gauge*     getGauge(const std::string& name, const std::string& help,
                        const Labels& labels = {});
    GaugeFunc* getGaugeFunc(const std::string& name, const std::string& help,
                            const Labels& labels, GaugeFunc::Callback cb);
    Histogram* getHistogram(const std::string& name, const std::string& help,
                            const Labels& labels = {},
                            const std::vector<double>& buckets = {});

    std::string RenderPrometheus();
};

typedef Singleton<Registry> RegistryMgr;

}
```

**指标清单**

| 指标 | 类型 | 标签 |
|------|------|------|
| `chen_server_connections` | Gauge | server, type |
| `chen_server_connections_accepted_total` | Counter | server, type |
| `chen_server_connections_rejected_total` | Counter | server, type |
| `chen_http_requests_total` | Counter | server, method, status, route |
| `chen_http_request_duration_seconds` | Histogram | server, method, route |
| `chen_http_active_requests` | Gauge | server |
| `chen_rpc_requests_total` | Counter | server, method, code |
| `chen_rpc_request_duration_seconds` | Histogram | server, method |
| `chen_fibers` | Gauge | - |
| `chen_fibers_created_total` | Counter | - |
| `chen_scheduler_queue_size` | Gauge | scheduler |
| `chen_timers` | Gauge | - |
| `chen_fds` | Gauge | - |
| `chen_log_queue_size` | Gauge | appender |
| `chen_log_dropped_total` | Counter | appender, policy |

**实现要点**

- Metric 对象堆分配，registry 只持有指针，避免 rehash 失效。
- Counter/Gauge/Histogram 使用 `std::atomic` + `memory_order_relaxed`，避免 `__sync_*` 全屏障在 arm64 等架构上的额外开销。
- Counter/Histogram 采用每线程分片（16~64 片，按 CPU 数取 2 的幂），热路径只更新本线程 shard，读取/渲染时聚合，避免跨核 cacheline 争用。
- Histogram 内部只递增命中的单个桶，渲染时计算累计 `le` 值，避免每次 observe 递增所有桶。
- label 基数控制：HTTP `route` 使用匹配到的 Servlet 注册路径，而不是原始 path；404 统一为 `not_found`。
- 补充 getter：`Scheduler::getTaskCount()`、`TimerManager::getTimerCount()`、`TcpServer::getActiveClientCount()`。
- 已有 `Fiber::GetFiberCount()` 直接接入。
- fd 数用 `/proc/self/fd` 统计。

**测试**

- Counter/Gauge/Histogram 并发自增
- label 区分、Prometheus 文本格式校验

### PR2 — 异步日志

**修改**

- `chen/log/log.h/.cc`
- `chen/application.cc`
- `docs/log-configuration.md`
- `tests/test_log_async.cc`

**配置（向后兼容，全部可选）**

```yaml
logs:
  - name: root
    appenders:
      - type: FileLogAppender
        file: /var/log/app.log
        async: true
        queue_size: 65536
        flush_interval_ms: 100
        overflow_policy: drop_oldest   # drop_oldest | drop_newest | block
```

**设计**

- 新增 `AsyncLogAppender : LogAppender`，包装真实 appender（File/Stdout）。
- `log()` 只把 `LogEvent` 入队，立即返回；后台线程批量取出并调用目标 appender 的 `log()`，格式化、轮转都在后台线程完成。
- 有界队列 + 条件变量；默认 `drop_oldest` 并计数，`block` 仅建议离线场景。
- `flush()` 需要同步语义：入队 flush 序号，等待后台线程处理完并调用目标 appender 的 `flush()`。
- 析构时停止线程、排空队列、join。

**fork / 退出**

- `LoggerMgr` 新增：
  - `beforeFork()`：flushAll + 停止所有异步线程
  - `afterForkParent()` / `afterForkChild()`：重新启动异步线程
  - `shutdown()`：flush + 停止线程
- `Application::spawnWorker()` 在 `fork()` 前后调用上述接口。
- `workerMain()` 的 `_exit(0)` 前、`reportWorkerFailed()` 的 `_exit(1)` 前都必须显式 `shutdown()`，否则异步队列日志会丢失。

**兼容性**

- v1.6.0 默认 `async: false`；示例配置开启，v1.7.0 再考虑默认开启。
- 现有 `test_log_size_rotate` 等同步测试无需改动。
- `LogAppenderDefine` 增加字段并同步 `operator==` / YAML 序列化。

**测试**

- 写入 N 条 → flush → 行数正确
- 队列满时三种溢出策略
- 大小/时间轮转仍正常
- fork 后子进程日志线程可继续工作

**新增**

- `chen/admin/admin_server.h/.cc`
- `chen/admin/README.md`
- `chen/util/service_state.h`
- `docs/observability.md`

**实现**

- `AdminServer : public http::HttpServer`，构造时注册：
  - `/metrics` → `RegistryMgr::GetInstance()->RenderPrometheus()`
  - `/healthz` → draining 时仍 200
  - `/readyz` → `ServiceState::IsReady()` 才 200
  - `/debug/servers` → server 状态、连接数、监听地址
  - `/debug/version` → `chen/<version>`
  - `/debug/config`（可选）→ `Config::Visit`，敏感 key 打码
- `RegisterBuiltInServers()` 注册 `"admin"`，设置 `m_type = "admin"`，确保模块 `getAllHttpServer()` 不会拿到它
- 配置示例：

```yaml
servers:
  - address: ["127.0.0.1:9101"]
    type: admin
    name: admin
    keepalive: 0
    timeout: 5000
    accept_worker: accept
    io_worker: io
```

- `Application::run_fiber()`：server start + 模块 `onServerUp()` 后置 `READY`
- `doGracefulShutdown()`：第一步置 `DRAINING`

**ServiceState**

```cpp
class ServiceState {
public:
    enum class Phase { INIT, READY, DRAINING, STOPPING };
    static void SetPhase(Phase);
    static Phase GetPhase();
    static bool IsReady();
    static bool IsDraining();
};
```

**安全**

- 默认只监听 `127.0.0.1`；文档明确不要暴露公网。
- `/debug/config` 对 `passwd/password/secret/token/key` 等 key 的值打码。
- v1.6.0 不做鉴权，列为 v1.7+。

**指标采集**

- Admin handler 调用 `RegistryMgr::GetInstance()->RenderPrometheus()`。
- `/metrics`、`/healthz`、`/readyz` 默认跳过访问日志。
- 业务自定义指标直接使用 `metrics` API 注册。

### PR4 — JSON 访问日志 + HTTP/RPC 指标

**修改**

- `chen/http/http_server.cc`

- 新增 `chen/http/access_log.h/.cc`

**JSON 格式（单行）**

```json
{"ts":"2026-10-17T12:34:56.789Z","request_id":"a1b2c3d4","pid":12345,
 "server":"game_http_server","proto":"http/1.1","remote":"1.2.3.4:54321",
 "method":"GET","path":"/api/user","query":"id=1","status":200,
 "bytes":123,"duration_ms":1.23,"route":"/api/user","ua":"..."}
```

**配置**

```yaml
http:
  access_log:
    enabled: true
    format: json
    sample_rate: 1.0
    skip_paths: ["/healthz", "/readyz", "/metrics"]
    header_whitelist: ["User-Agent", "X-Request-Id"]
```

**字段**

`ts, request_id, pid, server, proto, remote, method, path, query, status, bytes, duration_ms, route, ua`

**实现**

- 写入 `LOG_NAME("access")`（`bin/conf/system.yml` 已配置该 logger）。
- 若 `access` logger 没有 appender，则不输出，避免回退到 root。
- 请求 ID：优先取 `X-Request-Id`，否则生成短随机 ID，并回写响应头。
- `ServletDispatch::matchForRequest()` 增加可选 `route_label` 输出。
- HTTP/1.1 在 `handleClient` 计时；H2 在 `processStream` 计时。
- 同时更新 HTTP/RPC 指标：请求数、耗时直方图、活跃请求数。
- RPC route label 用方法名或 CmdID 字符串。

### PR5 — 优雅 Draining

**修改**

- `chen/socket/socket.h`（新增 `shutdown(int how)` 封装）
- `chen/tcp/tcp_server.h/.cc`
- `chen/application.cc`
- `chen/http/http_server.cc`
- `chen/http/h2_session.h/.cc`
- `chen/http/ws_server.cc`
- `chen/rpc/rpc_server.cc`
- `chen/game/game_server.cc`
- `tests/test_graceful_drain.cc`

**TcpServer 状态机**

```cpp
void beginDrain(uint64_t timeout_ms);
bool isDraining() const;
bool isDrained() const;          // m_activeClients 为空
void markInFlight(Socket::ptr);
void unmarkInFlight(Socket::ptr);
```

**beginDrain 行为**

1. 设置 `m_draining = true`，关闭监听 socket，停止 accept。
2. 遍历活跃连接：
   - 无在途请求：`shutdown(fd, SHUT_RD)`，让阻塞在 `recv` 的协程退出。
   - 有在途请求：保留，等待当前请求完成。
3. 记录 deadline；超时后强制 `close` 剩余连接。

**各协议接入**

| 协议 | 接入方式 |
|------|---------|
| HTTP/1.1 | header 解析完成后 `markInFlight`；响应发送后 `unmarkInFlight`；draining 时响应加 `Connection: close` 并退出循环；新请求返回 503 |
| HTTP/2 | draining 时提交 `GOAWAY(last_stream_id)`，不再接受新 stream；已有 stream 完成后关闭连接 |
| WebSocket | draining 时发送 CLOSE 帧（code 1001），然后关闭；超时强断 |
| RPC | 处理一条消息前 `markInFlight`，回包后 `unmarkInFlight`；draining 时回包后退出循环 |
| Game | 处理一个包前 mark，处理完 unmark；draining 后退出循环 |
| SSE/流式 | 视为长连接，draining 时直接关闭；超时兜底 |

**Application 流程改造**

替换 `chen/application.cc:283` 的 `closeAllClients()`：

```cpp
ServiceState::SetPhase(DRAINING);
for (auto& server : all_servers) server->beginDrain(drain_ms);
// 每 50ms 检查所有 server->isDrained()，或 deadline 到达
// 然后进入 onDeactivate / onUnload / WorkerMgr::stop()
```

- 停机（SIGTERM）与热重载旧 worker（SIGQUIT）复用同一流程。
- `isDrained()` 只看活跃连接数；长连接在 deadline 后强制关闭，避免无限等待。
- 日志中输出：开始 drain、剩余连接数、提前完成/超时强断数量。

## 五、验收标准

1. 压测下异步日志不阻塞 IO 线程；队列满时按策略丢弃并有指标。
2. `/metrics` 输出合法 Prometheus 格式，核心指标齐全且 label 基数可控。
3. `/readyz` 在启动、reload、drain、停机期间状态正确。
4. 停机与热重载时：
   - 在途 HTTP/RPC 请求正常完成
   - idle keep-alive 连接立即关闭
   - WebSocket 收到 1001 close
   - 超长连接在 deadline 后被强制关闭
5. 访问日志为单行 JSON，字段完整，健康检查路径不记录。
6. CI 能完成 Debug 构建 + ctest + ASAN，不破坏现有构建。
7. 现有测试与构建不回归。

## 六、风险与兼容性

| 风险 | 应对 |
|------|------|
| fork 时异步日志线程持有锁 | fork 前 `beforeFork()` 停止线程，子进程 `afterForkChild()` 重建 |
| LogEvent 循环引用 | 改 `weak_ptr<Logger>` + 保存 logger name |
| `_exit()` 丢日志 | 所有退出路径显式 `LoggerMgr::shutdown()` |
| draining 误杀在途请求 | 只在 header 解析完成后标记 in-flight；idle 连接才 `SHUT_RD` |
| 长连接拖住 drain | deadline 后强制关闭并记录 |
| Admin 暴露公网 | 默认 127.0.0.1，文档警示 |
| reload 期间 admin 短暂 503 | 文档说明；后续可做 master 聚合 |

**兼容性**：所有新增配置均为可选；默认保持同步日志与旧行为。draining 会改变热重载时连接关闭时机，需要写入 CHANGELOG。
